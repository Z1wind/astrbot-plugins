# 群趣事总结（astrbot_plugin_group_summary）

抓取群里最近的消息。有人 **@机器人** 说「总结 / 群总结 / 趣事 / 好玩的事」时，把最近消息按编号整体交给 LLM，让它挑出 **话题连贯** 的 2~3 段对话，再按编号取原话写成趣事，配上 **群友真实头像** 画成聊天截图风漫画，**只发一张图**，不刷文字。

除了 bot 自己缓存的消息，也可以**只读本机 QQ NT 的历史消息**，补全 bot 没收到/没缓存到的部分；本地消息带真实 QQ 号，头像可以直接按 QQ 号取。

## 用法（群聊）

```
@机器人 消息总结
@机器人 群总结
@机器人 最近有啥趣事
```

触发后机器人会：

1. 把最近消息按 `m001…` 编号，按时间顺序整体交给 LLM，让它挑 2~3 段话题连贯、彼此独立的对话
2. LLM 只返回消息编号，插件按编号从源消息取原话，并校验编号存在、跨度合理、不是纯媒体/XML
3. 抓取发送者头像并缓存，用 Pillow 画成漫画（标题 + 事件卡片 + 热度/参与人数徽章 + 聊天气泡）
4. **只发这一张图**；不先回“收到”，也不另发文字摘要；触发语本身不会进入趣闻素材

> 之前“文字摘要 + 图片”分两次 yield，AstrBot 的事件结果只保留一次，图片会被丢掉，所以现在是单次 image_result。

## 性能

一次完整总结拆成四段，日志会打印每段耗时：

- **本地补全**最多等 10 秒，超时回退 bot 缓存；
- 默认只把最近 **260 条**消息（`selection_max_messages`）交给 LLM，既保留上下文又控制 prompt 长度；
- **头像预热和 LLM 并行**，故事出来时头像通常已经缓存好；
- **LLM 最多等 15 秒**（`llm_timeout_seconds`），超时直接用候选原话兜底，不再让群等半分钟；
- 日志格式：`完成：总 9.8s｜本地 2.8s｜LLM 4.2s｜头像 0.3s｜渲染 0.4s｜320 条`。

## 怎么挑“趣事”

不再只给 LLM 4 个固定时间窗。固定 5 分钟窗会把前后两件事硬切在一起（例如把“M.2 没插槽”和“作业推销”拼成同一条），所以现在改为“LLM 选段 + 后端校验”：

- **全量编号**：最近消息按 `m001…` 编号，连同时间、昵称、内容一起给 LLM；它能看见话题怎么起、怎么接、什么时候结束；
- **只选编号**：LLM 输出 `ids`，不复制原文；插件按编号取源消息，因此不会出现“模型改写原话”；`[图片]/[视频]/[动画表情]` 占位符不会画进对话气泡；
- **硬约束**：提示词要求一段只讲一个话题，不能把两个话题拼在一起；标题要具体，描述不能加原文没有的动机或后续；
- **后端校验**：编号必须存在、不能跨太远（最多 60 条 / 30 分钟），过滤纯 `[图片]/[视频]/[动画表情]/XML`；一段必须至少两个不同的人说话，单人连续刷屏直接丢弃；`desc` 引号里的原话、提到的群友必须真的在选中消息里，否则改写成“谁说了哪句”的事实描述；
- **热度/人数**：按选中消息前后 90 秒的局部发言计算，不再拿两个选中片段中间夹着的十几分钟无关消息充数；
- **兜底**：LLM 失败或编号全不合法时，仍用原来的滑窗候选原话生成，至少保证有图。

固定滑窗现在只用于兜底和头像预热，不再决定最终讲哪几件事。图片上每件事显示「热度 N · M 人」，N 是选中消息前后 90 秒内的真实发言条数，M 是这些发言里的不同人数。

## 头像怎么取

- **QQ 官方（qq_official）**：先读消息原始对象 `raw_message.author.avatar`；实测群消息通常只有 `member_openid`，没有头像字段；
- **本地同名头像兜底**：如果本机其他插件（如 `astrbot_plugin_sheep_fund_rank`）已经有 `avatars/<昵称>.jpg`，按昵称复用这些真实头像；
- **OneBot / aiocqhttp**：优先取 `author/sender.avatar`；没有就用 QQ 号拼 `https://q1.qlogo.cn/g?b=qq&nk=<QQ号>&s=640`；
- 下载的头像按 URL 哈希缓存到插件数据目录 `avatars/`，同一头像只下一次；本地头像直接读取，不复制；
- 下载失败、超时、图片损坏时，回退到「彩色首字头像」，不会让整张图失败；
- 只缓存头像文件，不保存聊天记录到磁盘。

> QQ 官方群消息里的发送者是 `member_openid`，不是 QQ 号；因此官方接入时优先用 `author.avatar`，不会拿 openid 去拼 qlogo。

## 本地 QQ NT 历史（可选）

QQ 官方机器人只能收到平台推给它的消息，群里没 @ 它的消息可能根本到不了 bot，缓存自然不全。这个插件可以额外**只读**本机 QQ 的 `nt_msg.db`，在触发总结时补全最近 120 分钟：

- 默认只读配置里的目标群（`local_qq_group_qq`），只在 `local_qq_group_openid` 对应的 bot 群触发；
- 只查这个群，不查私聊、不查其他群；
- 触发时才读，不常驻、不后台轮询；
- 本地消息带 `senderQq`，头像直接拼 `https://q1.qlogo.cn/g?b=qq&nk=<QQ号>&s=640`，比 openid 首字准确；
- 群昵称/群名片从本地 `group_info.db` 的成员表补齐；
- 过滤机器人自己的发言：本地库会记录 bot 自己的回复，不剔除会被当成群友原话、还会虚增参与人数；
- 读不到 key / qq-mcp / Node、QQ 没登录、查询超时，都会**自动回退**到 bot 缓存，不影响总结；
- 插件本身不把原始聊天记录写盘；每次查询会给 qq-mcp 一个独立的临时 `QQ_MCP_HOME`，解密出的 SQLite 快照在查询结束立即删除，不在 `~/.qq-mcp/plain/` 留包含私聊的明文库。

依赖本机已有的 [`@powercess/qq-mcp`](https://www.npmjs.com/package/@powercess/qq-mcp)（Node）和 `~/.qq-mcp/qqkey`。路径可自动发现，也可在配置里手动指定 `local_qq_mcp` / `local_qq_node` / `local_qq_key_file`。

> 本地库包含你的私聊和其他群，所以插件只允许查 `local_qq_group_qq` 这一个群；不要把 `local_qq_group_openid` 留空后又在多群使用。key 只通过子进程环境变量传给 qq-mcp，不写日志、不进配置。

## 配置

在 AstrBot 管理面板 → 插件 → 群趣事总结 中可配置：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `max_msgs` | 120 | 每个群最多缓存的消息条数 |
| `window_minutes` | 120 | 总结时回溯的时间窗口（分钟） |
| `hotspot_window_minutes` | 5 | 热度滑窗大小（分钟） |
| `max_events` | 3 | 最多画几件趣事（1~3） |
| `selection_max_messages` | 260 | 送给 LLM 挑选的最近消息条数（60~500）；越大越准，prompt 也越长 |
| `llm_timeout_seconds` | 15 | 等 LLM 的最长秒数；超时直接用候选原话兜底，避免总结卡住 |
| `enabled_groups` | 空 | 只对这些群启用；留空 = 所有群。QQ 官方填群 openid，OneBot 填群号 |
| `local_qq_enabled` | 开 | 触发时只读本机 QQ NT 最近消息，补全 bot 缓存 |
| `local_qq_group_qq` | `0` | 要读的 QQ 群号；换群时和下一项一起改 |
| `local_qq_group_openid` | 当前羊村 openid | 只有这个 bot 群才用本地消息；留空 = 所有群都读同一个 QQ 群，通常不要留空 |
| `local_qq_limit` | 800 | 本地消息最多取多少条（50~2000） |
| `local_qq_mcp` | 空 | 可选：`mcp_call.mjs` 或 qq-mcp 包目录；留空自动找 |
| `local_qq_node` | 空 | 可选：`node.exe` 路径；留空自动找 |
| `local_qq_key_file` | 空 | 可选：qqkey 路径；留空用 `~/.qq-mcp/qqkey` |

## 说明与限制

- **能否抓到“所有”群消息取决于 QQ 接入方式**：
  - **QQ 官方机器人**需要在 QQ 开放平台开启「接收所有消息 / 全量模式（GROUP_MESSAGE_CREATE）」，否则只能收到 @它 的消息，缓存会漏掉没 @ 的消息；
  - **OneBot v11 / aiocqhttp（个人号协议端）** 一般能收到全部群消息。
- 消息只缓存在内存，重启后清空；头像文件会留在数据目录，可随时删除。
- 本地消息源依赖本机 `qq-mcp` + `qqkey`；QQ 大版本升级导致解密失效时，重新运行 `qq-mcp capture_offline_key`，或先关掉 `local_qq_enabled` 用 bot 缓存。
- 本地库是“本机 QQ 客户端已经同步到磁盘”的范围，不等同于服务端完整历史；刚换设备/刚登录时可能不全。
- 图片用本地 Pillow 绘制，需要中文字体（Windows 自带微软雅黑），不依赖远程渲染服务。
- 头像下载依赖外网；失败会自动用首字头像兜底，不影响总结。
- 群聊总结会展示发送者昵称和头像，属于群内可见信息；请只在信任的群里启用。

├── main.py            # 监听、缓存、本地补全、头像抓取、调 LLM、发单图
